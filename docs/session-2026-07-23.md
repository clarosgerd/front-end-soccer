### Contexto
Las semifinales y final del torneo AMIGOS no tienen equipos asignados porque la fase de grupos aún no se disputó.

## 6. Responsive Design

### Contexto
El sidebar fijo de 264px no era compatible con móvil. Se implementó responsive con hamburguesa y overlay.

### Archivo modificado
- **`src/components/domain/AppLayout.tsx`**

### Comportamiento

| Breakpoint | Sidebar | Header | Main |
|-----------|---------|--------|------|
| Mobile (< 768px) | Oculto, toggle con hamburguesa (Menu icon), overlay con backdrop | Botón hamburguesa visible, padding px-4 | Sin margin, padding p-4 |
| Desktop (≥ 768px) | Fijo visible, translate-x-0 | Sin hamburguesa, padding px-8 | ml-64, padding p-8 |

### Funcionalidades
- Auto-cierre del sidebar al navegar (`useEffect` en `location.pathname`)
- Click en backdrop cierra sidebar
- Transición slide-in/out con `translate-x` + `duration-200 ease-in-out`

## 8. Sistema de Roles y Permisos (4 Fases)

### Fase 1: Fundamentos de permisos

#### 1.1 Ownership de equipos
| Archivo | Cambio |
|---------|--------|
| `database/migrations/2026_07_23_400000_add_created_by_to_teams_table.php` | Nueva columna `created_by` nullable FK a users |
| `app/Models/Team.php` | `created_by` en fillable + relación `creator()` |
| `app/Http/Resources/TeamResource.php` | Incluye `created_by` |
| `app/Http/Controllers/TeamController.php` | `store()` setea `created_by = auth()->id()`, `bulkStore()` igual |

Equipos existentes quedan con `created_by = null` (pool global, visible para todos).

#### 1.2 Ownership checks faltantes

| Controller | Método | Check agregado |
|------------|--------|----------------|
| `TournamentController` | `toggleActive()` | Owner o admin |
| `GroupsController` | `update()` | Creator, admin global, o group admin |
| `GroupsController` | `destroy()` | Creator o admin |
| `GroupsController` | `toggleActive()` | Creator o admin |
| `TournamentGroupController` | `store()`, `update()`, `destroy()`, `addTeams()`, `removeTeam()`, `approve()`, `reject()` | Helper `canManageTournament()` + `canManageGroup()` |

#### 1.3 Reglas antes de predictores
| Controller | Método | Validación |
|------------|--------|------------|
| `GroupMembersController` | `joinRequest()` | Verifica scoring points > 0 antes de permitir unirse |
| `GroupMembersController` | `approve()` | Misma validación antes de aprobar |

Error 422: "El grupo debe tener reglas de scoring configuradas antes de aceptar predictores"

#### 1.4 Reglas frozen con predictores
| Controller | Método | Validación |
|------------|--------|------------|
| `GroupsController` | `update()` | Si hay >1 miembros aceptados, bloquea cambios en scoring fields |

Campos bloqueados: `exact_score_points`, `match_result_points`, `correct_goal_points`, `unique_exact_points`, `multiplier_dieciseisavos/octavos/cuartos/semifinal/final`

Error 422: "No se pueden modificar las reglas de scoring mientras hay predictores activos"

#### 1.5 Predictor/Admin puede actualizar resultados
| Controller | Cambio |
|------------|--------|
| `ManualMatchController` | Helper `canManageResults()` verifica: admin global, owner del torneo, O group admin de grupo vinculado al torneo |

### Fase 2: Rol Predictor/Admin

#### Nuevos endpoints

| Método | Ruta | Descripción |
|--------|------|-------------|
| `POST` | `/api/v1/tournament/{id}/assign-manager` | Admin asigna usuario como manager (crea grupo si no existe, agrega como group admin) |
| `POST` | `/api/v1/tournament/{id}/remove-manager` | Admin remueve manager (setea is_admin = 0) |
| `GET` | `/api/v1/tournament/{id}/managers` | Lista managers actuales del torneo |

#### Archivo modificado
- `app/Http/Controllers/TournamentController.php` — 3 nuevos métodos: `assignManager()`, `removeManager()`, `managers()`
- `routes/api.php` — 3 nuevas rutas

### Fase 3: Frontend UI por rol

#### Archivos creados

| Archivo | Descripción |
|---------|-------------|
| `src/hooks/useTournamentRole.ts` | Hook que determina rol: `admin`, `owner`, `manager`, `predictor`, `viewer` |
| `src/components/domain/TournamentRoleGuard.tsx` | Wrapper que muestra/oculta contenido según rol permitido |

#### Archivos modificados

| Archivo | Cambio |
|---------|--------|
| `src/api/endpoints/tournaments.ts` | Endpoints `managers()`, `assignManager()`, `removeManager()` |
| `src/hooks/useTournaments.ts` | Hooks `useTournamentManagers()`, `useAssignManager()`, `useRemoveManager()` |
| `src/pages/groups/GroupDetail.tsx` | Configurar, toggle, invite, approve/reject solo para admin/creator (`canManage`) |
| `src/components/domain/GroupSettingsForm.tsx` | Prop `rulesFrozen` — scoring fields disabled + badge "Bloqueado: hay predictores activos" |
| `src/components/ui/TextField.tsx` | Soporte visual para `disabled` prop (bg-slate-50, text-slate-400, cursor-not-allowed) |
| `src/pages/groups/GroupSettings.tsx` | Calcula `rulesFrozen` basado en cantidad de miembros aceptados |
| `src/pages/tournaments/TournamentManager.tsx` | Sección "Gestionar acceso (Managers)" visible solo para admin, con lista y form de asignación |

### Fase 4: Torneos públicos — Sync y Scoring
El flujo ya estaba implementado:
- Admin sincroniza torneo público (ESPN, football-data, etc.)
- Admin publica torneo
- Usuario crea grupo vinculado al torneo
- Usuario configura reglas → invita predictores
- Resultados se actualizan via sync o manualmente
- `ScoreMatchPredictions` job calcula puntajes automáticamente
